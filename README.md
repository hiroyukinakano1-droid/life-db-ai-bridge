# life-db-ai-bridge

AIチャット(Claude)から、Google Sheetsで管理する「人生DB(キャリア・実績・選考管理台帳)」へ、確認を挟んで1行追記するための橋渡しスクリプトです。

## 背景・課題

転職活動の応募企業・選考状況・実績エピソードをGoogle Sheetsで一元管理していましたが、AIチャットから直接スプレッドシートに書き込む標準的な手段がありませんでした。

## 解決策

Google Apps Script(GAS)をWebアプリとしてデプロイし、URLのパラメータで渡した内容をシートに1行追記する橋渡しを作りました。

1. AIが、追記したい内容を確認用のテーブルとして提示する
2. 人が内容を目で確認し、AIが生成したリンクをクリックする
3. リンク先(GASのdoGet)がトークンを確認し、シートに1行追記する

AIが即座に書き込むのではなく、必ず人の確認とクリックを挟む設計(Human-in-the-loop)です。確認テーブルとリンクの生成はAIチャット側の運用で、このリポジトリには含まれません。

## このリポジトリの内容

`addRowWebApp.js`(GAS側のWebアプリ本体、doGet関数)
- トークンによる簡易認証(一致しない場合は拒否)
- シートを名前またはインデックス番号で指定
- JSON配列で渡した内容を1行追記
- 追記した行の見た目を整える(折り返し、上揃え、フォントサイズ13)
- 結果をJSONで返す(成功時はシート名と行番号、失敗時はエラー内容)

## 使い方

1. 新規のGASプロジェクトにコードを貼る
2. `ACCESS_TOKEN` と `SPREADSHEET_ID` を自分の値に設定する
3. 「ウェブアプリ」としてデプロイする
4. `{WebアプリのURL}?token=...&sheet=シート名&data=["値1","値2",...]` の形で呼び出す(dataはURLエンコードする)

## 既知の制限と今後の改善案(未実装)

- トークンをURLのクエリパラメータで渡す簡易認証のため、本番運用ではPOSTやヘッダーでの認証が望ましい
- 数式として解釈される文字列(先頭が=など)への対策
- 存在しないシート名が指定された場合の自動作成
- 入力データの検証、実行失敗時のリトライ

## 関連

Gemini APIを呼び出して毎朝AIニュースや戦略アイデアを配信する仕組み(GAS、エラー時のアラートメール付き)は別プロジェクトで運用しており、このリポジトリには含まれません。
